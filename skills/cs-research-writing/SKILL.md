# 计算机学科科研写作

面向 CS / 智能系统 / 规划控制类稿件。默认语域是期刊书面语，不是口语润色。

若用户同时要去 AI 套话，先保结构与术语，再改句式；不要把期刊稿改成「笔者／回头看」。

## 先判断任务

| 用户要的 | 做 |
|---|---|
| 结构对照、SCI 怎么改 | 只改门面：引言、相关工作、实验导语、结论骨架 |
| 某句看不懂 / 不好听 | 先解释，再改成书面含义，不新增事实 |
| 去 AI 味 | 拆套式，不改主张、公式、数据 |
| 全文重写方法或实验 | 除非明确要求，否则不动引理、算法、表格数字 |

长文（>300 字或整章）先用几条列出将改什么，再改。用户说「按这个改 / 全部都改」后再动文件。

## SCI 审稿人怎么扫稿

按这个顺序找得到东西，比文采重要：

1. 摘要：问题缺陷 → 方法接口 → 保证条件 → 主结果
2. 引言末：编号贡献 2–3 条 + 后文路线一句
3. 相关工作及其明确导出的研究缺口
4. 问题形式化（短稿可与相关工作合并，主张依赖接口或失效机理时保留）
5. 方法
6. 实验：先统计对照，后机制案例
7. 结论一段，不堆表

学已发表短文的**目录与贡献写法**，不要学它们偏薄的实验。证据厚度以本稿主张为准。

## 引言（短）

只做三件事，文献综述移走：

1. 领域惯例 + **本文要修的机制缺陷**（各用具体机制说，不要「面临两项关键挑战」）
2. 动机图尽量靠前
3. 编号贡献 + 「第 x 节……」路线

贡献条目用 `enumerate`。条数 2–3；**长短可以不一**，主贡献写长。这是审稿导航，不是散文里的「其一/其二/其三」排比。

每条必须能在后文对上：定义 / 引理或算法 / 实验。写不出对应处的条目删掉。

## 相关工作与问题定义

按**求解结构**分组，不要按年份流水账。每类写清：它协调了什么、付出了什么代价（换求解链 / 多次调用 / 走廊内求解）。

相关工作可以独立成节，也可以在短稿中与问题定义合并。判断依据是内容职责而不是固定目录。若综述已经自然导出方法缺口，且问题节重复解释同一失效机理，则合为「相关工作与问题定义」，用一个小节归纳研究路线与缺口，另一个小节保留求解接口、必要定义和待解问题。

结构对比表只有在提供正文之外的横向比较时才保留。若表格只是逐项复述相邻段落，则删除表格并用一句话收束。不要为了像 IEEE 而拆出每节一段的空小节，一段一类即可。

## 压缩与英译准备

压缩先处理信息，再处理句法。重复主张、表图已经给出的数字、方法节会完整定义的预告和不影响结论的解释应当删除，不能只用近义词缩写。

中文底稿要便于转换为学术英文。正文以中长复句为主，每句围绕一个中心结论容纳两到三个有层级的分句，并用「其中」「从而」「同时」「因而」「尽管」或条件结构明确关系。不能为了简洁把论证拆成连续短句，无法并入主句的次要短句应当删除。

当用户要求去除 AI 式标点时，可见中文叙述不使用中文分号和冒号，包括标题、摘要、正文、图注、表注与关键词行。不要把它们机械替换为句号，而应删除次要信息，或将保留内容改写为主从、因果、条件或并列结构。数学表达式、代码标识和文献原始字段不受此限制。

摘要沿「问题缺陷、方法主干、理论或接口贡献、主实验结果」形成单段论证，通常只保留一到两个最能支撑结论的数字。实验段落由表格承担完整数值，正文只解释比较对象、主要差异和必要的统计证据。

## 实验

节首用一到两个复句划开两类证据。

- **统计对照**：精确性、配对场景、检验、消融、灵敏度
- **机制案例**：少量确定性场景、系统/规划链接入

案例用来解释机制，不代替大样本。有配对设计、置信区间、显著性就写在统计段，不要塞进结论复述全表。

内部批次名、协议号、种子文件名不进正文。需要可复现时说明各方法在固定随机种子下求解同一生成场景，并比较配对差值。细节放补充材料或仓库，正文不报 `miku-random-v2` 这类标签。

### 检验对象、术语与证据范围

实验句先写清比较对象和指标，再写统计方法或观察结果，最后限定能够推出的结论。不要用“快速方法是否正确”“完整方法是否有效”代替可检验命题，应写成“是否得到相同的单截面最优宽度”或“比较无碰撞终点到达率与规划耗时”。

算法名必须与方法节的公式或定理锚点一致。若方法节定义的是“$O(k\log k)$ 最大间隙扫描”和“$2^k$ 组合枚举最优解”，实验节不得另称“扫描程序”“快速扫描”“穷举结果”。指标名也应在摘要、实验设置、表头和结果段保持一致，百分点表示比例的绝对差，不写成“相对提升若干个百分点”，首次出现的缩写需给出中文含义。

“该检验不用于衡量……”一类备忘式否定，应改为同一复句中的对象与边界，例如先说明检验核对的是单截面最优宽度，再由此说明它不能衡量整条轨迹的横向跟踪误差。不要补写“误差为零”等实验没有测量的新结论。

统计对照承担总体差异估计，少量确定性场景承担机制定位。机制案例只能说明观察到的构型，不得写成总体差异的完整来源，也不得由少数均通过的场景推出方法普遍“没有破坏”原能力。消融表中的每个组件必须能回指到方法正文或算法步骤；若回指缺失，应依据已有实现补足定义，无法确认时删除该消融项而非根据名称臆造机制。

## 结论（一段六拍）

对齐常见 IEEE 短结论，不要再写第三段「意义/推论」：

1. 提出什么方法
2. 相对谁、扩大或改变了什么（可行域 / 接口 / 复杂度）
3. 给出什么保证（引理、充分条件、最优性）
4. 最终仍表述为什么标准问题（QP、MIP、DP……）
5. 实验一句话：比谁好在哪；**只留 1–2 个主数字**
6. 后续工作**只写一件**具体的事

禁止：具有重要意义、前景广阔、完整证据链、 complementary 套话。
局限若必须出现，单独一句（「当前证据来自仿真，不能代替实车」），不要和条件句推论挤在一句里。

## 句子级：内部黑话

出现下列说法，改成读者不进仓库也懂的书面语：

| 删 | 写成 |
|---|---|
| 协议 `xxx-v2`、实验标签 | 固定种子、配对设计、场景规模 |
| 独立 oracle | 穷举最优解 / 组合枚举对照 |
| 扫描程序、快速扫描 | 与方法节一致的算法名，如 $O(k\log k)$ 最大间隙扫描 |
| 穷举结果 | $2^k$ 组合枚举最优解 |
| 关键实现分支、与代码中一致 | 需单独处理的几何情形；与定义的中心宽度一致 |
| 模块类名 +「语义」（如 PathBoundsDecider） | 规划阶段的通用名（SL 边界构造） |
| 官方场景、三幕、平台演示 | 系统提供的场景；三类行为；接入验证 |
| 见补充材料（实际没有） | 删 |
| Baseline（中文稿） | 基线（首次可注明即 B0） |

术语可以留（QP、ST、同伦、扫描线），但**第一次出现要有定义或公式锚点**。读者问「X 是什么」说明正文没定义，补一句，不要只在对话里解释。

实现备忘（「下游不得再减一次车宽」）改成含义：坐标系是什么、量还表示什么、后面不再重复计入什么。

## 保真与语域

- 不新增事实、案例、数据、文献。
- 中文期刊：少用第一人称；用「本文」。不要为去 AI 味而口语化。
- 英文 SCI：可用 we；贡献用 `itemize`/`enumerate`。
- 修改 LaTeX 长稿或用户要求闭环完成时，编译并检查未定义引用、重复标签、错误引用和异常分页，同时记录修改前后的正文计数。若环境无法编译，应明确报告缺失条件。

## 改门面时的检查

- [ ] 引言能否 1 分钟读完贡献
- [ ] 相关工作是否落到本文接口，独立或合并的节结构是否与篇幅相称
- [ ] 实验节首是否区分统计 / 案例
- [ ] 检验是否写清比较对象、指标与能够支持的结论范围
- [ ] 摘要、正文、表头中的算法名和指标名是否一致，消融项是否能回指方法步骤
- [ ] 结论是否六拍、主数字 ≤2 个、后续只一件
- [ ] 用户要求时，可见中文叙述是否无分号和冒号，且没有变成连续短句
- [ ] 摘要、相关工作与问题定义、实验叙述是否删除了表图或方法节的重复信息
- [ ] 无仓库内部名、无空「补充材料」、无「具有重要意义」
- [ ] 方法、定理、表内数字未被顺便改掉，LaTeX 能否编译且交叉引用完整
