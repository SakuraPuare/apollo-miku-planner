# 三区/四区稿投稿前二次校正计划

## 目标

在不扩大实验含义、不虚构实车测试、不把内部验证工具写入论文的前提下，完成 P0、P1、P2 三阶段闭环，使论文具备三区尝试和四区稳妥投稿条件。

## P0：证据与数据闭环（必须先完成）

1. 用 `CLAIM_EVIDENCE_MATRIX.md` 逐条审计摘要、正文、图表、结论和投稿信。
2. 冻结 3,500 场景、消融、联合参考和 700 场景回归包的版本关系，并把原始 CSV/JSON、种子、配置和哈希纳入补充材料归档。
3. 整理 Apollo 版本、代码提交、修改文件、BUILD/编译信息、场景标识、车辆模型、Dreamview/CyberRT 运行日志、关键帧和轨迹输出。
4. 将 Apollo 工程证据收口为“核心边界生成、接口传递和典型行为验证”，不写实车道路测试。
5. 论文投稿文件不出现内部形式化验证工具名称或实现细节；内部工程仅用于自检。

## P1：竞争力与期刊适配（P0 后完成）

1. 在同一公开场景/同一评测协议下加入至少两个可审计外部基线，或明确把外部结果降级为诊断而不作性能领先结论。
2. 增加系统级指标：完整规划周期 P50/P95/P99、最小安全间距、最小 TTC、路径长度、通行时间、加速度、jerk、降级停车率和时间窗违反次数。
3. 增加车辆可执行性证据：动力学约束、轨迹跟踪误差或 Apollo 车辆模型下的可行性检查。
4. 按 IET Intelligent Transport Systems、Journal of Intelligent Transportation Systems 和四区备选期刊分别检查 scope、摘要重点、关键词、图表和投稿信。
5. 统一最近相关工作的逐篇差异和基线解释，不把内部对照包装成外部 SOTA。

## P2：三轮交叉审阅与最终验收

1. 理论审阅：检查定义、假设、定理、复杂度和边界条件。
2. 自动驾驶工程审阅：检查 Apollo 场景、车辆模型、C++ 接口、日志、轨迹和实车措辞。
3. 期刊编辑审阅：检查 scope、创新、图表、外部基线、复现材料、desk-reject 风险和格式。
4. 修复所有 major/minor 问题后，运行 Python 测试、数据一致性检查、LaTeX 编译、PDF 视觉检查和投稿材料检查。
5. 只有在所有门禁通过后，才确定第一投稿目标和保底期刊。

## 验收条件

- 每个定量结论可回溯到原始 CSV/JSON 和生成命令。
- 每个工程结论可回溯到场景、配置、日志、关键帧或轨迹。
- 论文不声称真实实车测试、不声称连续全局最优、不声称完整端到端形式化验证。
- 外部基线公平性、数据版本、样本数量和统计方法没有矛盾。
- 目标期刊信息在投稿前重新核验，且至少准备一份三区方案和一份四区方案。
