## major（必改，且均为改文字即可清，零数据成本）

### major-1〔实验方法 / 内部自洽〕M4≈M5 的 0.82 分缺口与"走廊未激活"论断自相矛盾

定位：L767-768（M5=100.00 / M4=99.18）、L777（"M4与M5之间质量微分由权重决定"）、L779（"走廊约束未触发活跃边界…关闭它只是少了一组几乎不生效的速度约束"）。

问题：评分以 M5 自身为归一化分母（L749 明示），M5≡100 是定义。L779 又断言走廊在全部 4 个压力场景"未触发活跃边界"。若该断言为真，则关闭走廊的 M4 在路径几何、速度几何、通行、平顺四类指标上与 M5 **逐点相同**，唯一可能不同的只有 0.15 权重的计算开销维度——而 L801 已自认 QP 墙钟耗时是受调度/缓存/频率波动影响的单次采样。由此 M4 的 0.82 分落差几乎只能来自单次测时噪声，而非任何"质量微分"。这与 L777"同通过数变体之间相对排序确由权重决定…权重对均通过变体之间的质量微分，例如 M4 与 M5 之间，同样成立"的措辞直接冲突：M4–M5 之间根本没有质量差，只有计算开销维度的测时噪声。更进一步，这一漏洞会回灌到刚清掉的 NEW-major-1：M2 与 M3 的 2.63 分差同样含 0.15 的计算开销维度，其中也混入了单次测时噪声，故"2.63 完全来自四维加权几何平均、依赖权重取值"的归因不完整。

为何是 major 而非 minor：这是 v4 为回应 round03 而新写的防御文字（L777）自身不自洽，审稿人会拿 L779 与 L777 当场对照打脸，且牵连到刚修好的权重论断。

处置〔改文字能修〕：明确把 M4 与 M5 的 0.82 落差归因于 0.15 计算开销维度的单次测时噪声，而非质量差；相应把 L777"M4 与 M5 之间…质量微分同样成立"删去或改为"M4 与 M5 在质量维度逐点相同，0.82 仅反映计算开销维度的单次测时抖动"；并在 M2/M3 处补一句"其中计算开销分量含单次测时噪声，2.63 分差的稳健部分来自前三维"。

### major-2〔实验方法 / 防御性框定〕舒适性优势实质只由 C1、C2 两个动态场景支撑，C3/C4 近乎平凡且数值异常未解释

定位：L663（正文）、表 tab:exp_comfort（L674-677）。

问题：可比场景舒适性对照（L663）是"约束前置改善纵向平顺"这一结论的唯一连续指标证据。但表中 C3 为 $|a_x|=0.14/0.14$、$|j|=0.14/0.14$，C4 为 $|a_x|=0.11/0.11$、$|j|=0.11/0.11$——Baseline 与 MIKU 在 C3/C4 上**逐项相同**，且纵向加速度幅值与 jerk 幅值取到**完全相同的两位小数**。两个物理量纲不同的指标在两种算法上同时取到同一数值，强烈提示 C3/C4 的纵向轨迹近乎匀速、指标贴在数值地板上，舒适性对照在这两个场景上不承载信息。于是"MIKU 改善纵向平顺"实际只由 C1、C2 两个动态场景支撑（C1 jerk 8.19→1.62、C2 9.33→1.25），而这两个恰恰都派生自 Baseline 失效构型。L663 仅一句"C3 窄路场景下两者…均接近零"带过 C3，对 C4 的 $a_x{=}j{=}0.11$ 完全相同未作任何解释，读者会怀疑是抽取或复制错误。

处置〔改文字能修〕：一句话解释 C3/C4 纵向近匀速、$a_x$ 与 $j$ 同处数值地板（说明数值相同非抄录错误）；并把舒适性结论收敛为"纵向平顺改善由 C1、C2 两个动态可比场景体现，C3/C4 因纵向近匀速不承载平顺区分"。数据冻结不动，只补口径。

## minor（建议改，均为改文字或补现成数据）

### minor-1〔语言/文风〕横向加速度单位写成 m/s³

定位：L663"横向加速度峰值由 Baseline 的近零分别升至 1.07 与 1.45\,m/s$^3$""C4 场景 MIKU 横向加速度峰值 1.87\,m/s$^3$与 Baseline 的 1.93\,m/s$^3$"。横向加速度应为 m/s²，表 tab:exp_comfort 表头 $|a_y|_{\max}$ 已正确标 m/s²。正文笔误。改 m/s³→m/s²。

### minor-2〔实验方法〕蒙特卡洛扰动协议未交代

定位：L784"对五个权重施加 ±20\% 扰动，做 100 次蒙特卡洛采样"。未说明：扰动分布（均匀/正态）、五因子是否独立扰动、扰动后是否重新归一化使权重和回到 1.0。五因子权重 0.30/0.20/0.15/0.10/0.25 本和为 1，独立 ±20\% 后破坏归一，是否重归一直接影响结果含义。补一句协议说明（若冻结资料可追溯则照写，不可追溯则如实写所采用的做法）。属可复现性透明度。

### minor-3〔实验方法/叙事〕QP 耗时为 Python 复现内的同程序对比，非 Apollo C++ 运行时

定位：L587（"以 Python 复现 Apollo Planning 主要计算环节…二次规划统一交由 OSQP"）、L682-723（效率对照）。效率结论是 Baseline-Python 对 MIKU-Python，反映的是约束规模差异的算法级开销，不是 Apollo C++ 生产运行时。建议在效率小节补一句明示，避免审稿人误读为 Apollo 实测运行时；这也与 L795"桌面平台不外推"形成完整口径。

### minor-4〔实验方法〕C2 中 Baseline 56.41 ms 离群成因未交代

### minor-6〔实验方法/叙事〕综合评分构造偏自定义，复杂度未对结论增益
