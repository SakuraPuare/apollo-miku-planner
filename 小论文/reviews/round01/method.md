## P0 致命（答辩/审稿会被毙）

### P0-1 〔实验方法 / 需新实验或重新框定〕通过率判据 `s_end ≥ s_max − 1 m` 不含碰撞与安全校验，而 MIKU 的核心机制是压缩安全裕度

定位：`v1.tex` L515（判据定义）、L48/L520/L539（4/4、8/8、29.3% 全部建立在此判据上）、L626–628（灵敏度只测“通行带宽度越界概率”，非碰撞）。

问题：全文最重的结论（压力场景 Baseline 0/4 → MIKU 4/4、汇总 8/8）由唯一判据 $P_{\mathrm{pass}}$ 定义，而该判据仅检查“仿真终点纵向到达 $s_{\max}-1$ m”，即只验证“走到了终点”，不验证“走的过程中没撞、没越界、与障碍物保持了安全间距”。这在普通论文里是小瑕疵，在本文里是致命的——因为 MIKU 的第一个组件（差异化裕度 $\delta_i$）做的恰恰是把安全裕度从统一值压到下限 $0.10$ m 以“释放通行空间”（L48、L708）。也就是说，本文用一个“不看安全间距”的判据，去证明一个“靠压缩安全间距换通过”的方法成功了。方法审会立刻反问：MIKU 的 4/4 里有没有“贴着障碍物 0.10 m 擦过去”甚至几何上已侵入的案例？现有判据无法排除，灵敏度的“单因子越界概率 0”测的是通行带宽度不越工程阈值，不是车体不碰障碍物，堵不上这个窟窿。

为何是 P0 而非 major：这不是“缺一个锦上添花的指标”，而是“核心成功判据与核心机制的作用对象正交”。审稿人有理由认为 4/4 这个数字本身缺乏安全语义支撑，进而质疑全文主结论的有效性。

可改 vs 数据红线：**数据红线挡住，需新实验**。冻结宏中无任何 clearance / min_dist / 横向间距类指标（已 grep 确认 `_experiment_metrics.tex` 无此字段），靠改文字无法补出安全间距数据。
- 文字层面（必做、立即可做）：把 $P_{\mathrm{pass}}$ 诚实改名为“纵向到达率”或明确其语义边界，并在判据定义处与局限节明文承认“通过=纵向到达终点，不含碰撞/侵入/最小间距校验”。L643 已把“最小安全间距列为后续工作”，但这只承认“没测舒适-安全指标”，没承认“连通过判据本身都不含碰撞校验”——二者严重程度不同，必须升格表述。
- 数据层面（记 MODIFICATIONS 需新实验）：补一组最小间距 / 几何侵入检测，至少对 MIKU 的 4 个压力通过案例报告 min_clearance，证明 $\delta_i=0.10$ m 下未发生侵入。这是把 P0 真正降级为可接受局限的唯一硬路径。

## major 必改

### M-1 〔实验方法 / 数据红线挡住，需重新框定〕可比场景“QP 总耗时 19.16→6.26 ms（约 3×）”几乎全部来自单个离群场景，且 MIKU 在其中一个可比场景反而更慢

定位：`v1.tex` L48（摘要）、L558、L565、L710（结论）、L539 附近。冻结源：`_experiment_metrics.tex` M5–M8（=可比场景 C1–C4）QpTotal。

问题（本轮新发现，前文任何地方未披露）：拆开可比场景 4 个 QpTotal——
- M5：Baseline 10.44 / MIKU **12.53**（MIKU 慢 20%）
- M6：Baseline 56.41 / MIKU 3.17（Baseline 慢 17.8×，离群点）
- M7：Baseline 4.11 / MIKU 3.75（基本持平）
- M8：Baseline 5.68 / MIKU 5.58（基本持平）

均值 19.16→6.26 的“3 倍提速”几乎完全由 M6 一个离群场景拉动；去掉 M6，其余三个可比场景 MIKU 并无效率优势，甚至在 M5 更慢。把“3× 提速”写进摘要 L48 和结论 L710 作为效率卖点，方法审拆均值即破——这是典型的“均值被单点支配”，二区审稿人对 n=4 的均值本就敏感，一旦发现 4 个点里 1 个支配、1 个反向，会直接判定“效率结论不成立或被夸大”。讽刺的是 L546 已经很谨慎地把压力场景的耗时判为“不可比”，却没对可比场景内部做同样的诚实拆解。

可改 vs 红线：**数据不改，靠重新框定 + 披露**。
- 必须把 4 个可比场景的 QpTotal 逐场景列出（数据已在冻结宏，合法），不能只给均值。
- 摘要/结论的“3× 提速”表述需收敛：要么改为“可比场景中 MIKU 求解耗时与 Baseline 同量级，个别 Baseline 退化场景下显著更快”，要么明确标注“均值受单场景支配，中位数约 1.7×，且存在 MIKU 更慢的场景（M5）”。
- 真要主张效率优势而不被拆均值，需新实验（多场景扩样或重复测时），记 MODIFICATIONS 需新实验类。

### M-2 〔实验方法 / 需新实验〕QP 耗时为单次运行、报到小数点后两位，墙钟计时无方差无重复

定位：`v1.tex` L490（平台）、L548–560（耗时表，6.26/5.56/19.16 等两位小数）、L641（局限：确定性单次运行）。

问题：L641 承认“确定性仿真单次运行”，但墙钟 QP 耗时（OSQP 求解时间）本质不是确定性量——同一输入多次运行受 CPU 调度、缓存、频率波动影响，毫秒级测时尤甚。把 6.26 ms、5.58 ms 这类值报到两位小数且无 ±std、无重复次数，方法审会判定“计时方法学不达标”。L641 把“单次确定性”当挡箭牌，但它只对“路径/速度几何输出”成立，对“求解墙钟时间”不成立，二者被混为一谈。

可改 vs 红线：
- 文字（必做）：明确区分“几何结果确定性可复现”与“墙钟耗时为单次采样、未做重复与方差刻画”，把后者列入局限，降低小数位的隐含精度暗示。
- 数据（记 MODIFICATIONS 需新实验）：耗时指标做 N 次重复报 mean±std 或中位数+IQR。在不补实验前提下，至少不能把单次毫秒值当作可信效率结论的硬证据。

### M-3 〔实验方法〕可比场景 C1–C4 是压力场景 P1–P4 的人工微调派生，非独立场景，构造效度（construct validity）未声明

定位：`v1.tex` L494、L505–508（C 由 P“逐一复制 + 轻量调整”而来）、L513。

问题：C1–C4 不是独立采样的新工况，而是“把 P1–P4 调到 Baseline 恰好能过”的派生场景（L505：延长时间窗 / 外移停车 / 改非对称 / 调到贪心临界侧）。这意味着整个 8 场景套件是为“先证 Baseline 失败、再证常规情形持平”这条叙事量身定制的闭环，C 组的“持平”几乎是被构造出来的必然结果，而非独立证据。方法审会指出：用“调到对方刚好能过”的派生场景来论证“常规情形两者持平”，存在选择性构造，证据强度被高估。局限节 L639 谈了“压力场景偏向 Baseline 失效边界”，但没谈“可比场景是压力场景的反向人工微调”这一构造效度问题。

可改 vs 红线：**改文字可修**。在场景设置节与局限节明文声明：C 组系 P 组的最小扰动派生，目的是控制变量地观察“放宽到可达后”的指标，不构成独立工况采样；“持平”结论的外部效度因此受限。诚实声明即可化解，瞒着不说才是雷。

### M-4 〔实验方法 / Apollo 工程交叉〕Baseline 未启用 LaneBorrow，而 P4 恰是借道场景，比较公平性未讨论

定位：`v1.tex` L508（P4“单车道维修封闭加借道”）、L513（Baseline 失败口径）、全文 grep 无 “LaneBorrow”。GOAL 第 6 节明列此为已知必被攻击点，要求文字讨论启用后的预期差异——稿件目前**完全没碰**。

问题：P4 是“单车道封闭 + 借道”，这正是 Apollo `LaneBorrowPath` / lane-borrow 场景的设计触发条件。若 Baseline 的 `PathBoundsDecider` 在主车道 BLOCKED 后本可由 LaneBorrow 借相邻车道通过，而本文的 Baseline 未启用该路径，则“Baseline 0/4”部分建立在一个被削弱的对照上。L513 已诚实界定“Baseline 失败 = 路径阶段单独处理动态障碍物的口径”，缓解了一部分，但完全不提 LaneBorrow，等于回避了方法审一定会问的“你的 Baseline 是不是被阉割了”。

可改 vs 红线：**框定可改文字，证伪需新实验**。
- 文字（必做）：补一段说明本文 Baseline 口径不含 LaneBorrow 的理由（如 LaneBorrow 依赖相邻车道可用性、属另一条决策支路、与本文聚焦的“路径阶段时间维度缺失”是正交机制），并讨论启用后 P4 的预期差异。
- 数据（记 MODIFICATIONS 需新实验）：要真正堵死，需补“Baseline + LaneBorrow”对照，证明即便允许借道，时间维度缺失导致的失效仍存在。否则 P4 的失效归因始终有“其实是没开 LaneBorrow”的替代解释。

### M-5 〔实验方法 / 叙事〕走廊注入（C5）在全部 8 场景未被激活，与“三组件通道”的核心叙事冲突，定量必要性为零

定位：`v1.tex` L610/L621（M4 关闭走廊 = 99.18，差 0.82 近似持平）、L645（局限：走廊未激活）、L48/C 节核心叙事（三组件之一= 时间怎么传）。

问题：稿件已经很诚实地处理了 M4≈M5（L621 的解释写得好，不否定机制、归因于场景未激活、价值由架构论证给出）。但方法审要把这层捅得更深：C5 不是“在压力场景未激活”，而是**在全部 8 个场景都没产生活跃约束**（消融只在 P1–P4，C 组也未见其生效证据）。这意味着本文三大支柱之一在整个实验中定量贡献恒为 0，却仍作为核心 insight“时间怎么传”的落地组件出现在摘要和结论。这是“叙事的三足”与“实验的两足”之间的结构性不一致。L621 + L645 的认怂能缓解“是否否定机制”，但缓解不了“一个全程未激活的组件能否算作经过验证的贡献”。

可改 vs 红线：**部分改文字，彻底解决需新实验**。
- 文字（必做）：在贡献声明与摘要层面，把 C5 的地位明确降格为“架构完备性组件，其定量价值在本实验场景集内未被触发，留待动态冲突密集场景验证”，不要让读者误以为三组件都在实验中各自立功。
- 数据（记 MODIFICATIONS 需新实验）：补一个能触发走廊活跃边界的动态冲突场景（交叉口冲突点 / 多动态时间窗交织），让 C5 至少有一次定量生效，否则“三组件”在实证上始终是“两组件 + 一个设计论证”。

### M-6 〔实验方法 / 叙事〕灵敏度“翻转不改变通行结果”是推断而非实测，超出所测量的指标

定位：`v1.tex` L626–628（57% 翻转率、最大相对偏差 6.4%、越界概率 0）、L628（“翻转改变的只是排序名次，并不改变最终避让方向决策与通行结果”）。冻结源：`_sensitivity_macros.tex` 实测量为 FlipRate / MaxRelDev / ExceedProb / MaxAbsDev，均为通行带宽度/排序层面的量。

问题：蒙特卡洛实际测的是“通行带宽度相对偏差”“排序翻转率”“单因子越界概率”，这些都是中间几何量。但 L628 的结论句“并不改变……通行结果”是对“最终是否通过”的断言，而灵敏度实验**没有对每次扰动重跑通过/失败判定**（否则应有翻转后通过率的统计，冻结宏中无此量）。这是把“宽度偏差小”外推成“通行结果不变”，超出了所测范围。57% 是个扎眼的数字，方法审会盯着它问“翻转后你真重跑过通行结果吗”，而当前证据只到“宽度偏差 6.4%、越界 0”。

可改 vs 红线：**改文字可修**。把结论严格收敛到“实测表明权重扰动下通行带宽度相对偏差 ≤6.4%、无单因子越界，翻转集中于威胁度差 <0.02 的同类锥之间、对应 $\delta_i$ 变化 <0.01 m”，删去或弱化“不改变通行结果”这一未实测的外推；若要保留通行结果不变的主张，需补“翻转样本重跑通过判定”的实验（记 MODIFICATIONS）。

## minor 建议

### m-1 〔实验方法 / 内部一致性〕引言用“汇总 21.56→5.56 ms”，实验节却自判压力组耗时不可比，前后口径打架

定位：`v1.tex` L65（引言：QP 平均总耗时 21.56→5.56 ms）vs L546（实验节：压力场景 Baseline 降级，耗时不构成比较依据）vs L48/L710（摘要、结论只用可比组 19.16→6.26）。

问题：摘要与结论已统一到“只用可比组 19.16→6.26”这条诚实口径，但引言 L65 仍把含降级污染的“汇总 21.56→5.56”当作卖点抛出。同一篇稿子，引言用了实验节明确判为“不可比”的数。建议引言改用可比组数字，或删去汇总耗时、只留通过率与速度概览，与实验节口径对齐。改文字即可。

### m-2 〔实验方法〕可比场景轨迹质量（加速度/jerk 峰值）有文字断言但无数据表支撑

定位：`v1.tex` L541（“C1–C2 纵向加速度峰值与 jerk 峰值低于 Baseline”“C3 横向加速度峰值接近零”）、L710（结论复述）。冻结源：`_experiment_metrics.tex` 各场景 MaxAbsA/MaxAbsJerk/MaxAbsALat 齐全（如 M1 Baseline jerk 8.19→MIKU 1.62）。

问题：舒适性优势目前只有文字描述，无表。数据其实都在冻结宏里且对 MIKU 有利（如 jerk 8.19→1.62 很能打），不列出来可惜，也让“C1–C2 更平顺”成了无据断言。建议补一张可比场景的 $|a_x|_{\max}$ / $|a_y|_{\max}$ / $|j|_{\max}$ 对照表，把已有合法数据用足。纯属把现成数据补成表，无需新实验。

### m-3 〔实验方法〕综合评分函数权重 0.30/0.30/0.25/0.15 为人工指定，且硬门使总分实质退化为通过率函数

定位：`v1.tex` L591（四维权重）、L593 式(eq:exp_score_scn)、L619（“综合评分很大程度反映通过率差异”）。

问题：L619 已自认“评分主要反映通过率”，那么式(7)那套四维加权几何平均 + 硬门 + 失败折半的精巧构造，实际信息量约等于“通过率排序”。权重 0.30/0.30/0.25/0.15 无来源说明，方法审会问“为何是这组权重，换一组结论是否稳健”。建议要么补一句权重选取依据 + 对权重不敏感的说明，要么坦白“综合评分主要用于把通过率与通过场景内质量合成单一序，对权重选取不敏感，因区分度主要来自硬门”。改文字可修。

### m-4 〔实验方法〕灵敏度只扰动威胁度 5 权重，未扰动聚类半径/分组阈值/$\delta_i$ 区间/障碍物位置，鲁棒性主张范围偏窄

定位：`v1.tex` L626（仅 5 个威胁度权重 ±20%）、L492（聚类半径 10 m、分组阈值 12 m、$\delta_i\in[0.10,0.40]$ 均为定值未扰动）。

问题：MIKU 的关键超参不止威胁度权重，还有聚类半径、纵向分组阈值、$\delta_i$ 区间，以及对预测轨迹的依赖。当前灵敏度只覆盖威胁度权重一类，却在结论层面给人“算法鲁棒”的整体印象。建议把鲁棒性主张严格限定为“对威胁度权重取值鲁棒”，并在局限/未来工作中点明其余超参与感知-预测噪声的敏感性尚未评估。改文字可修。

### m-5 〔实验方法 / 表述〕“OSQP 对约束数量增量不敏感、不改变稀疏结构”属性能断言，无微基准支撑

定位：`v1.tex` L565（“走廊约束以标准 ST 上界注入，OSQP 对约束数量增量不敏感，不改变 QP 稀疏结构”）。

问题：“不改变稀疏结构”是结构性事实（盒式上界收紧确实不动 Hessian/等式约束，可成立），但“对约束数量增量不敏感”是一句性能断言，没有微基准或求解迭代数据支撑。建议把后半句收敛为“注入仅收紧上界向量若干分量，不增加约束行数、不改变 Hessian 与等式约束的稀疏模式”，这是可由结构论证的；删去无据的“求解器对增量不敏感”性能口吻。改文字可修。
