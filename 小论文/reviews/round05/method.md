## minor（建议改，均改文字或补现成口径，零数据成本）

### minor-1〔实验方法 / 内部自洽〕「七项指标」与正文枚举的六项对不上（新发现）

定位：L617「每个场景计算七项指标，覆盖通行能力、轨迹舒适性与求解开销三类」。

问题：紧随其后的枚举为——通行能力两项（纵向到达率 $P_{\mathrm{pass}}$、平均速度 $\bar v$），轨迹舒适性三项（$|a_x|_{\max}$、$|a_y|_{\max}$、$|j|_{\max}$），求解开销一项（路径 QP 与速度 QP 合计的总耗时 $t_{\mathrm{qp}}$），合计 **6 项**，与「七项」差一。这是一处确定的计数错位，细心的审稿人会当场点出，影响方法陈述的严谨印象。

处置〔改文字能修〕：把「七项」改为「六项」；或若意图把 $t_{\mathrm{qp}}$ 拆为路径 QP 与速度 QP 两项以凑七，则需在枚举处同步拆分并在结果表中体现，二者择一，不能正文说七、枚举给六。

### minor-2〔实验方法 / 叙事〕综合评分仍含未交代依据的「折半惩罚」系数，构造偏自定义（round04 minor-6 遗留）

定位：L749-754，特别是 L754「全局得分对所有压力场景再做几何平均并放大至百分制，若任一场景因硬门得零分则退回算术平均并折半惩罚」。

问题：round04 已把该评分的定位收敛为「在很大程度上反映通过率差异」（L777），缓解了边际信息问题。但「折半惩罚」的系数 0.5 仍无任何依据交代，而它恰恰是 M1（25.29）、M2（37.13）、M3（34.50）三个含零分场景变体得分的直接决定因素——这三个数都由「算术平均后乘 0.5」的回退分支算出（可反算核对：M2 三场景通过、得分 $\approx 0.5\times\tfrac{3}{4}\times100\approx37.5$，与 37.13 吻合）。即同通过数变体的相对排序与三档落差的绝对数值，均依赖这个自由系数。表 tab:exp_ablation_score 的「通过数」列已含同等的粗分层信息。

处置〔改文字能修，二选一〕：(a) 补一句证成几何平均否决性与 0.5 折半系数的设计依据（例如对照 Apollo 默认代价项的某种量级，或声明 0.5 为保守经验取值并说明结论对其不敏感）；或 (b) 把综合评分降级为通过数表的附属说明，主结论回归「通过数」这一无自由参数的客观量，综合评分仅作辅助排序参考。本轮倾向 (b)，可一并消除「自定义评分体系被质疑」的风险面。

### minor-3〔实验方法 / 防御性框定〕「满足实时性要求」以事实口吻断言，与「桌面平台不外推」的自我设限存在张力

定位：L559（理论章）「整体复杂度…在 Apollo 11.0 的 100 ms 规划周期约束下满足实时性要求」；对照 L795「QP 求解耗时等开销指标反映 Intel i9-14900HX 桌面环境的表现，车载嵌入式平台的实时性须另行评估，本工作不就此外推」与 L723「同程序对比…非 Apollo C++ 生产运行时」。

问题：唯一的耗时证据是 Python 复现的算法级耗时（可比场景 6.26 ms、压力场景 4.86 ms），既非 C++ 生产运行时、又被明文声明不外推到嵌入式平台。在此前提下，L559 以「满足实时性要求」的肯定句式断言，与全文别处的设限口径不一致，审稿人会拿 L795 对照 L559 质疑。复杂度论证（$O(n\log n+K)$）只支撑「具备实时可行性的算法阶」，不等于「在车载平台已满足 100 ms」这一经验结论。

处置〔改文字能修〕：把 L559 收敛为可证范围，例如「在算法复杂度上具备满足 100 ms 周期的可行性，桌面复现耗时远低于该周期，车载平台的实时性须另行评估」，与 L795/L723 口径对齐。

### minor-4〔实验方法〕可比场景派生改变了速度区间，削弱其作为「纯控制」的说服力，建议显式点明控制了什么、没控制什么

定位：L641（MIKU 压力 4.66 高于可比 4.47，归因为两组「可通行里程与限速设置不同」）、L596 / L797（C1–C4 由 P1–P4 施加最小扰动派生）。

问题：v5 已诚实声明可比场景非独立采样、外部效度受限（L797），这是到位的。但仍存一处可加强：放宽时间窗或障碍物位置以恢复 Baseline 可达，同时也改变了可达速度区间（L641 自承），因此 C1–C4 控制的是「障碍物构型族」，并未控制「速度区间/限速」。当前文字把可比场景同时用于「通行能力持平」（L622）与「轨迹质量/求解开销对照」（L596）两个结论，而速度区间的漂移意味着舒适性与速度类指标的跨组比较口径不完全对齐。

处置〔改文字能修，轻量〕：在 L596 或 L641 补一句界定——可比场景控制的是障碍物构型，未控制速度区间，故其结论限于「同等可达前提下的构型级对照」，速度类指标不跨 P 组与 C 组直接比较。属对既有设限的精确化，可与 minor 一并顺手清，亦可并入 L797。

## 数据红线挡住、需新实验（文字防御均在位，本轮不重复扣分；供主编归 MODIFICATIONS「⑧需新实验或人工决策」类）

以下五项 v5 均已在局限节诚实承认并降级，本轮仅核验防御是否在位（均在位），并对优先级重新排序。其中前两项是本文卡在二区还是三区的分水岭，自 round03 起持续遗留，须在主编层面推进，非本审能在稿内闭合。

1. 〔需新实验，最高优先级，自 round03 遗留〕**走廊注入组件的激活场景验证**。L779/L805 已诚实归因 M4≈M5 因当前 4 个压力场景未触发走廊活跃边界，其定量贡献「由架构设计论证而非本组消融数据给出」。问题在于：全文标题级 insight「经 \texttt{STDrivableBoundary} 注入速度 QP」这一半，至今无任何实验证据，注入侧仅靠架构论证支撑（路径侧的时变投影由 M1 消融验证）。要把这半个核心 insight 坐实，唯一硬解是补能触发活跃时间窗约束的动态冲突密集场景（多动态障碍物时间窗交织或交叉口冲突点）。补齐后 M4–M5 才会出现真实质量差，0.82 的噪声解读随之消解。

2. 〔需人工先核可否从冻结几何反算，性价比最高，自 round04 遗留〕**最小安全间距 / 几何侵入校验**。L617、L803 已承认通过判据仅判纵向到达、不含碰撞校验，4/4 与差异化裕度取下限 $\delta_i=0.10$\,m 缺安全间距的直接支撑——这是全文最重结论唯一未闭合的安全缺口。**关键提示**：L587 称数值复现程序对每个场景输出 SL 路径边界与 ST 走廊几何；若该几何已在冻结资料内，则最小间距可由路径 $l(s)$ 与障碍物投影 $O_i$ **后处理反算**，属对既有冻结输出的派生分析而非重跑仿真，不触碰数据冻结红线。建议主编先核实冻结资料是否含逐场景 SL 几何；若含，此项从「新仿真」降为「分析补齐」，按 SPEC B 记 MODIFICATIONS 走人工确认产出新数字的口径即可低成本闭合。

3. 〔需新实验〕**QP 墙钟耗时多次重复 + 方差/中位数**。L801 已自认单次采样、毫秒级不具两位小数精度。效率结论（哪怕收敛为「同量级、个别场景显著更快」）若要具统计意义需 N 次重复报 mean±std 或中位数+IQR。文字防御在位。

4. 〔需新实验〕**灵敏度的分布刻画 + 翻转样本通行结果重跑**（round04 minor-5 遗留 + L801 自认）。100 次 MC 仍只报极值（最大相对偏差 6.4%、最坏翻转率 57%、其余三场景翻转率 0），未给通行带宽度偏差的 mean±std 或四场景翻转率逐场景表；场景四 57% 翻转是否最终改变通行结果亦未对翻转样本重跑确证（L801 已声明未做）。若冻结资料含逐次样本则可补一组分布摘要（属对既有样本的统计而非新实验），需人工核实样本是否冻结；翻转样本重跑则属新实验。建议主编核实逐样本可得性后定夺。

5. 〔需新实验，方法审视角下比威胁度权重更要害〕**感知与预测噪声的灵敏度**。L786 已自认未评估。MIKU 整条通道吃的是预测轨迹 $O_i(\tau(s))$ 与上周期反推的 $\tau(s)$，而现有灵敏度只扰动威胁度五权重，完全未触及预测/感知误差对时变投影与走廊的传播。文字防御在位，建议在未来工作把「预测误差→时变边界→通行带」的传播评估单列为优先项。
