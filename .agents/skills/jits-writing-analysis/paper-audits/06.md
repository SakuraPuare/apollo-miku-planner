# 06 单篇论文审计：Wi-Fi 探针与 AGT 车辆载客量估计

> **证据边界**：仅分析这一篇论文，不能把任何现象直接当作 *Journal of Intelligent Transportation Systems* 的普遍规范。源文件是 MinerU 转写稿；乱码项目符号、公式字符（如 `t ¼ 6`）、缺失的小节 Markdown 标题和前置网页图片不是可靠的排版证据。

## 定位、类型与受众

- **题名**：*Vehicle occupancy estimation in Automated Guideway Transit via deep learning with Wi-Fi probe requests*。题名采用“目标任务 + 场景 + 方法/数据源”结构，检索词密度高。两位作者来自土木与环境工程系；刊载信息为 2026, 30(4), 726–744，DOI `10.1080/15472450.2025.2499590`（L1–7, L31–35）。
- **领域/文章类型**：智能交通、公共交通运营、无线感知与时序预测交叉领域的**实证方法评估/现场试点研究**。贡献不是新网络结构，而是完整流程、复杂真实场景验证，以及对既有去随机化/去噪方法的负面结果（L62–76, L260–270）。
- **核心受众**：交通工程与 ITS 研究者、Wi-Fi/移动感知和机器学习研究者；应用受众是交通机构的规划、调度和乘客信息系统人员。引言先对政策制定者、机构和乘客说明价值，结论再落到班次、车辆调度与实时拥挤信息（L47–49, L437–441）。

## 结构与修辞推进

1. **摘要**为单段“问题重要性 → 框架 → 既有方法失效 → 真实试点 → 深度学习胜出 → 机构价值”，不塞公式或复杂参数（L37–39）。
2. **引言**依次建立运营需求、Wi-Fi 的成本/实时/隐私优势、探针机制、MAC 随机化缺口、AGT 特有困难；随后把**三项贡献、三项发现、全文路线**分别编号，读者很快获得文章契约（L47–78）。
3. **综述**不是作者罗列：先按部署范围分类，再分别处理 MAC 随机化、主动/被动采集、乘客/噪声分离、预测模型；两张表把“研究—方法—局限”结构化，末尾单设 2.4 节汇总四个缺口，并逐一回指章节（L80–140）。
4. **框架/方法/实验分工清楚**：第 3 节讲硬件、采集、清洗和真值聚合；第 4 节讲候选算法、伪代码和评价量；第 5 节按“场景 → 两阶段预实验 → 正式试点 → 特征 → ML → DL → 讨论 → 外推”逐层收敛（L142–304, L306–435）。
5. **讨论与结论**先复述比较性结论，再解释反常结果，承认三类现实误差，给出地区迁移步骤；结论用“发现 → 运营价值 → 未来工作”收束（L415–441）。

## 可复用写作技巧与行为规范

- 用第一人称复数明确承担动作（`we propose/test/acknowledge`），背景事实紧跟作者—年份引文；首次出现写全称并给缩写，此后用 AGT、AFC、RSSI、RF、XGB、CRNN、CDBLSTM。
- 把**负面结果写成知识贡献**：不是隐藏 DBSCAN/FCM 失败，而是先说明文献为何看似可行，再用真实高密度场景反证，最后转向 `random_bursts` 等可用特征（L102–107, L378–389）。
- 参数不只报数，还给“双证据”：`−60 dBm` 同时来自空场预实验和文献；空场 634 帧中 97% 低于 `−80 dBm`，40 ft 内设备强于 `−60 dBm`（L178–184, L316–322）。
- 用微型算例解释难懂的数据规则：2:21 的 `(30+28)/2=29`；2:27 的 `(38+37+37+61)/4=43.25`。再用 Stop 14–16 不足 1 min 的旅程解释为何时间指纹不可行（L188–208）。
- 结果段遵循“**表/图定位句 → 主结果 → 机制解释 → 选择决定**”，并显式报告反例与线路差异，而不是只摘最佳数字（L378–399）。
- 对推测原因使用 `likely/may/believe`，对事实给具体场景与交叉引用；各表、图、公式在正文出现前后均被引用。

## 方法、数据与验证证据

- 设备为 TP-Link TL-WN722N（2.4–2.4835 GHz）+ Le Potato 单板机 + Wireshark；Pyshark 从 `pcapng` 提取数据（L152–165）。五步清洗依次筛 frame type 0/subtype 4、广播目的地址、单播、删除 RSSI `<−60 dBm`、对非随机 MAC 做 OUI 手机识别（L167–184）。
- 真值为人工车内计数并按 1 min 聚合。预实验包括空场测试，以及 2023-02-17 两趟各 45 min 的 FIU shuttle（平均 11,416 帧/趟）；正式数据为 Miami-Dade Metromover 的 OMNI/BRICKELL 两线，2023-03-27 至 04-09、工作日和周末、超过 100 趟、每天 4 h（L186–208, L312–336）。
- 原始帧数分别为 OMNI 训练/测试 3,280,221/961,998、BRICKELL 4,136,054/1,038,604；五步后为 107,405/19,598 和 171,911/36,630（原始量的约 3.27%/2.04%/4.16%/3.53%）（Table 4, L328–330）。过滤后随机 MAC 占 97.4%–98.0%；载客量长尾至 64，高于所引既有研究通常 `<35` 的范围（Table 5/Fig. 9, L338–357）。
- 特征覆盖地址数、随机地址数、数据率、SSID 状态、帧长、持续时间、burst、RSSI 分箱、站点指示变量（Table 6）。RF/XGB 用训练集 5 折交叉验证选特征；深度模型用全部特征和此前 `t=5…11` min，比较 CRNN/CDBLSTM（L361–397）。评价为 MAE、RMSE、MAPE、R²及按最大载客量归一化的 NMAE/NRMSE，共 6 个编号公式（L272–304）。
- 最佳汇总：OMNI 的 CRNN 报 MAE 3.55、RMSE 4.48、R² 0.45；BRICKELL 的 CDBLSTM 报 3.90、5.19、0.65。相对各线 RF，MAE 约降低 19.7% 与 12.0%。最佳流程反而是 **no clustering + no fuzzy**（Tables 7–9; L378–403）。跨研究比较在最大载客量 64 且包含随机 MAC 时给 NMAE 5.55%、NRMSE 7.00%（Table 10, L411–423）。

## 数值/统计报告风格与风险

- 优点是始终带单位、场景、训练/测试、线路和指标方向；同时报告 MAE/RMSE/MAPE/R²，不只报单一“准确率”。零载客量使 BRICKELL 训练 MAPE 为 `∞`，作者在表下注明原因（L369–395）。
- **不要照搬的弱点**：文中用 `significantly outperform`，但未见显著性检验、置信区间或重复训练方差；训练/测试划分方式、样本分钟数、网络层/超参数、随机种子也未在转写正文中充分交代。MAPE 遇零失效，应预先规定处理并辅以 WAPE/sMAPE。人工真值误差虽坦承，却无双人计数一致性或误差界。跨论文按最大载客量归一化并不等于同数据集公平比较。
- 引言称 8–10 个滞后最稳健，但表中线路/架构最佳值包含 `t=6,8,9,10`；结论的 `prove` 和“复杂场景成功即可推广到更简单系统”也偏强。后续稿宜改为“supports/provides evidence”，并做跨日期、线路或城市外部验证。
