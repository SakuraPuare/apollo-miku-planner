# Paper 04 审计：Collaborative optimization method for intelligent and connected single-route bus operation

## 身份、领域、类型与受众

- **书目信息**：Xuemei Zhou 等，*Journal of Intelligent Transportation Systems* 30(5), 969–987；DOI `10.1080/15472450.2025.2531352`。2023-09-26 收稿、2025-06-25 修回、2025-07-05 接收、2025-07-14 在线发表。标题采用“**方法 + for + 明确对象/情境**”结构，直接限定 intelligent/connected、single-route bus。
- **研究类型**：智能交通/公交运营控制的**非线性双目标建模 + 混合进化算法 + 合成仿真**论文；不是现场试验，也没有真实线路数据验证。
- **主要受众**：公交调度与可靠性研究者、ITS/V2X 与优化控制工程师、运营企业；文末又用三条政策建议主动覆盖市政/交通管理者（V2X 走廊、动态优先立法、绩效补贴与算法审计）。

## 结构与修辞动作

1. **Abstract** 用一段完成“提出协同策略 → 列出发车间隔/停站/速度三模块 → 命名 NSGA II-DE 求解器 → 概述四类改善 → 宣称应用价值”，但不报任何数值。
2. **Introduction** 从拥堵、道路资源与碳中和建立公共价值，转到 5G/V2X、大数据和自动驾驶的技术可行性，再定义 connected environment、缩小到 SRB，最后给逐节 roadmap（§1）。
3. **Literature review** 先以控制空间划分站内/区间控制，再按 holding、skip-stop、speed regulation、signal priority 组织文献；结尾从“多为单一控制、只看前车”收束出“前后车 + 多层协同”的缺口，并编号列贡献（§2）。
4. **Method** 依次写控制直觉、公式化、8 条简化假设、35 项符号表、运营方/乘客双目标、3 类约束、混合算法与实施步骤（§3）。这种“机制叙述 → 数学定义 → 可执行流程”对工程论文很有效。
5. **Evaluation** 按“场景与参数 → Pareto 选解 → 敏感性 → 可靠性/车头时距/旅行时间/速度 → 综合指标 → 算法效率”展开（§4）；讨论嵌在结果中，没有独立 Discussion。
6. **Conclusion** 一段回扣缺口、三模块、求解器和总体效果，随后明确理想通信/专用道假设及未覆盖的信号延误、多线路协同，并把它们一一转成未来工作。

## 方法、数据与验证证据

- 决策变量是分时发车间隔、站点额外停站时间和区间诱导速度；目标为公交企业运营成本 `C1` 与乘客候车+车内时间成本 `C2`。正文有 **16 个编号公式**：控制律 (1)–(8)、成本 (9)–(13)、发车/停站/速度约束 (14)–(16)。每组公式后立即释义变量与工程含义。
- 合成线路长 **5 km、11 站、平均站距 500 m**；速度 `[10,25] km/h`，发车间隔 `[2,10] min`，额外停站 `[3,90] s`；成本参数为 `μ1=4 yuan/min`、`μ2=0.5 yuan/min`。表 2–3 给出峰/平峰下 11 站的客流到达与下车率区间。
- NSGA II-DE 设置：父代 **30**、交叉率 **0.9**、变异率 **0.2**、声称迭代 **200** 代，得到 **28** 组 Pareto 解；以两成本之和最小选出平峰/工作时段 **578 s**、高峰 **295 s**，`α1=0.17`、`α2=0.43`。
- 五个场景构成近似消融链：无控制、仅停站、仅看前车的停站+速度、前后车协同但固定发车间隔、前后车协同且按峰/平峰改变间隔。评价指标覆盖到站轨迹、车头时距变异系数与偏差范围、平均旅行时间、平均速度；另有参数敏感性和 NSGA-II 基线。
- 表 5 的可核验效果：相对场景 1，协同方案平峰的 headway CV 从 **0.21 降至 0.04**（约 −81%），偏差范围 **655→98 s**（约 −85%）；高峰 CV **0.52→0.07**（约 −86.5%），偏差范围 **1019→117 s**（约 −88.5%），平均旅行时间 **1551→1487 s**，速度 **4.11→4.34 m/s**。这类“绝对值 + 相对变化 + 机制解释”比只写 improved 更可复用。

## 数值/统计写法与证据边界

- 优点是单位齐全、范围/参数/算法超参数公开，并报告区间（如场景 5 高峰 headway deviation `[-47,60] s`）和少量百分比（场景 4 相对场景 5 的旅行时间 −3.6%/＋6.6%）。结果段常用“观察 → 原因（客流、停站、扰动传播）→ 运营含义”的三句链。
- 但文中多次使用 **significant/significantly**，没有重复次数、均值方差、置信区间、显著性检验、效应量或不确定性分析；这些词只能理解为定性强调，不能模仿为统计结论。算法效率也未报告运行时间、复杂度、hypervolume/IGD 或多随机种子分布。

## 可复用技巧

- 把每个缺口绑定为一组可检查对象：**只看前车 → 前后车控制律；单一控制 → 发车/停站/速度三模块；成本冲突 → Pareto 解；落地疑问 → 五场景、敏感性与运营指标**。
- 先用符号表和假设锁定边界，再给目标、约束、算法伪步骤；实验中让场景逐级加入模块，使每张图承担一种证据角色。
- 结果不要止于排名：同时报稳定性、效率、企业成本与乘客成本，并解释反常结果（如 holding 增加旅行时间）；结论用“已证范围—现实缺口—对应未来扩展”收束。
