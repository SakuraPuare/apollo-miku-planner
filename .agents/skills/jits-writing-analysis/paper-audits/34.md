# 单篇审计 34：A new recourse algorithm for school bus routing with overlapped routes and process flexibility

## 定位、类型与受众

- **出处与主题**：Huayan Shang 等，*Journal of Intelligent Transportation Systems* 30(3), 673–695，DOI `10.1080/15472450.2025.2487808`。研究异质车队、随机学生需求和最大乘车时间约束下的校车路径问题（SBRSD）。
- **论文类型**：方法/算法创新论文，采用“跨领域概念迁移（制造过程柔性）+ 网络结构设计 + 两阶段启发式/补救算法 + 仿真 + 单校真实案例”的证据组合，而非纯理论证明或纯实证研究。
- **核心受众**：智能交通与车辆路径研究者、运筹优化/随机规划与元启发式研究者；次级受众是校车调度者、教育交通管理部门和需要在车队成本、线路熟悉度与服务可靠性之间权衡的实践者。摘要和引言把“安全、熟悉线路、减少操作错误”写成管理价值，使技术贡献可被非算法读者理解。

## 结构与论证推进

1. **摘要采用五步闭环**：现实重要性 → 随机需求造成的缺口 → 两项方法贡献（open-chain `k`-overlapped-route network、new recourse algorithm）→ 运作机制 → 数值与经验研究验证、双目标优势。关键词直接覆盖机制、算法、问题与不确定性。
2. **引言先建立决策张力**：固定先验线路稳定但容量利用差；每日重优化距离短却增加司机换线风险。随后把“部分柔性”定位为折中方案，最后给出问题边界、作用机制、效果主张和逐节路线图（Section 1）。
3. **综述按问题域而非年代堆叠**：Section 2.1 讲随机校车路径，2.2 讲补救策略，2.3 将两条文献链汇合为缺口。Table 1 用“互联线路、时间约束、里程约束、需求揭示时点”等维度证明本文组合尚未出现；之后用四条编号贡献逐一对应网络、算法和验证。
4. **由直观到形式化再到检验**：Section 3 用制造系统类比与符号表奠基；Section 4 从 dedicated/open chain/closed chain/full connection 分类过渡到新网络；Section 5 给出两阶段算法；Sections 6–7 依次做受控仿真和真实案例；Section 8 用四条结论回扣四条贡献并只保留一个明确未来方向。

## 写作手法与可复用技巧

- **先比较极端方案，再提出中间机制**：以“固定线路 vs. 完全重优化”和“无柔性 vs. 全柔性”两组对照，让 `k` 重叠的必要性自然出现。
- **同一概念反复换表征**：文字定义 primary/additional/extended route（Section 3.2），网络图（Figures 3–4），情景图（Figure 6），伪代码（Algorithm 2），最后用真实逐车路线（Tables 4–6）落地。复杂算法因此同时具备直觉、规则和可执行描述。
- **贡献不是形容词，而是“现有做法—差异—收益”句式**：例如由“固定数量顾客重叠”改为“最多后续 `k` 辆车的整条 primary routes 重叠”，再解释容量共享与线路熟悉度。
- **结果段遵循“读图方法 → 观察 → 数字例证 → 机制解释”**：Figure 7 先解释 violin 的长度、宽度和分位线，再比较分布；随后解释低需求下剩余容量更多，因而优化更明显。Figure 8 明示 0% 基线及负值区域，避免只报有利结果。
- **用稳定缩写组织多臂实验**：`OR1/OR2` 表示仅第一阶段的 ACO/GA，`R1/R2` 表示各自再加补救阶段（Section 6.2.1），便于跨图一致比较。

## 模型、算法、数据与验证

- **假设/边界**：单仓、异质容量、每车每日一趟、从学校空车出发并返回；各站需求为相互独立、已知分布的非负整数，早晨发车前揭示；受最大乘车时间、容量和里程约束（Section 3.2）。
- **模型**：Appendix A 的目标式 (A1) 用大常数 `M0` 优先最小化车辆数、其次最小化总路程；(A2)–(A3) 起终仓，(A4) 流平衡，(A5)–(A6) 时序/最长时间，(A7) 服务分配，(A8) 容量，(A9) 变量域。共 9 个编号公式。
- **算法**：第一阶段分别用 ACO/GA 解 TSP，并遍历每个起点及正反方向生成 `2n` 个序列；按最大站点需求做路线分割，再从 `2n` 个 SBRP 解中选目标最小者（Algorithm 1；ACO 细节见 Algorithm B1）。第二阶段按车辆顺序处理已揭示需求：跳过已服务/零需求站，以余量进入后续最多 `k` 条 primary routes，触碰容量/时间/里程约束即返回；若扩展线路需求已被前车满足则不发车（Algorithm 2；Figure 6(b–f)）。
- **仿真设计**：10 km × 10 km 笛卡尔区域；9 种规模（10、20、…、90 个站）；固定随机种子 1–30 模拟 30 天；车速 60 km/h，容量 30/40/50/60；均匀、低需求正态、高需求正态三类需求；硬件为 3.30 GHz i7-11370H/16 GB RAM（Section 6.1）。基线既包括第一阶段自身，也包括相同实例/分布/规模下的 ALNS 与 VNS。
- **真实验证**：北京西城区外国语小学，18 个站，以 ACO 先验线路的 Day 0 为基线，再观察连续 3 天（Section 7）。这是可行性/应用性展示，不是大样本外部有效性检验。

## 讨论、结论与规范性前后置材料

- 结果讨论强调三条机制：补救阶段整体有效；第一阶段解质量会传导至最终结果，ACO/R1 优于 GA/R2；低需求最利于容量共享。作者也如实指出 R2 在不少情景会增加距离（Figure 8），并在 80 站高需求下承认车辆数优势缩小。
- Section 8 用编号结论重述容量共享、双目标改善、首阶段敏感性与北京案例。唯一明示局限是需求只在发车前揭示且途中不再变化；未来工作指向动态随机需求。线路熟悉度/减少错误是由线路相似性（Figures 11–12）推断，未直接测量司机错误、安全或满意度。
- 前置材料含标题、作者与双单位、结构化程度较低的单段摘要、article history（Received 19 Aug 2024; Revised 16 Mar 2025; Accepted 28 Mar 2025）和 5 个关键词。后置材料依次为 Conclusion、Disclosure（无潜在利益冲突）、Funding（NSFC 71971144）、References、三个附录。未见 data availability、ethics、author contributions 或代码仓库声明。

## 复用模板与注意事项

可复用的成稿骨架是：**双方案矛盾 → 可迁移理论 → 本域约束为何需改造 → 特征矩阵证明缺口 → 编号贡献 → 图示定义 → 模型/伪代码 → 多规模×多需求×多种子仿真 → 强基线 → 真实案例 → 贡献对照式结论 → 单独局限**。每个关键机制至少配“定义图 + 情景图 + 算法 + 数值实例”之一，关键主张同时给绝对值和相对改善。

不可照搬之处：单校 3 天不足以支持广泛实践结论；30 个固定种子之外缺少敏感性、显著性与置信区间；距离使用“units”而非清晰物理单位；未披露数据/代码；`k` 增大与效果改善仅由三天案例提示，不能当因果结论。MinerU 文本还存在 OCR/版面错序（Figures 12–14 落在 Conclusion 标题后）、Table 2 中 `e_j` 重复定义、Table C1 内容缺失等问题，正式写作必须回查原 PDF，不能继承提取错误。
